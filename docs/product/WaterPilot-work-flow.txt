1. Understand the current water situation
The user first selects an area, apartment community, ward, or locality.
Example:
Koramangala, Bengaluru

WaterPilot then builds a local water profile using available geospatial and historical data.
It looks at things like:
- rainfall
- groundwater trends
- surface water
- water demand
- reliable supply
- water deficit
- flood risk
- water quality
- land cover / built-up area
- nearby communities sharing the same water system
The user does not need to understand raw GIS data.
They see a simple summary like:
Water stress: Moderate
Summer shortage likely in: 74 days
Demand: 12.4 MLD
Reliable supply: 10.8 MLD
Current deficit: 1.6 MLD

So Screen 1 answers:
“What is my situation today?”

Technically, this comes from a combination of Earth Engine, BigQuery and any validated public datasets we onboard.
2. Test a future scenario
Now the user can ask:
“What if something changes?”

This step is optional.
Examples:
What if rainfall drops by 20%?

What if tanker supply reduces by 50%?

What if demand rises by 15%?

What if groundwater falls further?

The user can either select a predefined scenario or type their own.
For example:
“What if tanker supply stops for 30 days?”

WaterPilot first interprets the sentence.
Gemini converts it into structured parameters like:
Scenario:
Tanker supply reduction

Reduction:
100%

Duration:
30 days

Then a deterministic simulation engine calculates the effect.
It might show:
Water deficit: 1.6 → 2.8 MLD
Reliability: 87% → 72%
Summer shortage: 74 days → 46 days
Risk: Moderate → High

Important distinction:
Gemini understands the request. The simulation engine calculates the result.

We do not ask Gemini to invent water-balance numbers.
3. Set the goal
Once the user understands the present and possible future, WaterPilot asks:
“What do you want to achieve?”

They can choose a quick goal such as:
- reduce summer shortage
- improve groundwater
- reduce water bills
- prevent flooding
- improve water quality
or enter a custom goal:
“Reduce tanker dependency by at least 50%.”

WaterPilot converts that into a structured objective.
Example:
Primary goal:
Reduce tanker dependency

Target:
At least 50%

Scope:
Selected community

The user then adds constraints:
Budget: ₹10 lakh
Maximum implementation time: 60 days
Priority: Maximum impact

So now WaterPilot knows both:
what the user wants
and
what constraints they have
4. Generate intervention plans
The system now evaluates possible interventions.
Examples:
- rainwater harvesting
- recharge wells
- leakage reduction
- greywater reuse
- conservation measures
- storage improvements
- stormwater capture
WaterPilot should not show the user 20 technical options.
Instead, it creates a few plans.
Example:
Plan A — Balanced Plan
Rainwater harvesting + recharge wells + leakage repair
Cost: ₹8.2L
Time: 45–60 days
Expected deficit reduction: 58%
Plan B — Lowest Cost
Leakage repair + basic rainwater harvesting
Cost: ₹4.2L
Time: 30–45 days
Expected deficit reduction: 32%
Plan C — Highest Impact
Wider rainwater harvesting + recharge wells + reuse
Cost: ₹12.8L
Time: 60–90 days
Expected deficit reduction: 74%
Now the user can compare actual trade-offs.
This screen answers:
“What are my realistic choices?”

5. Check the neighbour impact
This is where WaterPilot becomes much more interesting.
A solution may help one community while hurting another.
For example:
Add more borewells

Your community might get more water temporarily.
But if surrounding communities depend on the same groundwater system, they may be affected.
So every plan is checked against the wider system.
Example:
Plan A
Your community: +18%
Shared aquifer: +5%
Neighbour impact: Positive
versus:
Borewell-heavy plan
Your community: +22%
Shared aquifer: -8%
Nearby communities: -4%
WaterPilot can flag:
False Resilience

Meaning:
The community looks safer locally, but the wider water system gets worse.

This is one of the strongest parts of the product.
6. Show cost, time and first benefit
For each plan, WaterPilot should answer three simple questions.
How much?
Estimated cost: ₹8.2 lakh

How long to build?
Implementation: 45–60 days

When will we see benefit?
First visible benefit: approximately 2 months / after significant rainfall

This is important because users often do not care about a purely technical "impact score."
They care about:
Can we afford it?
How long does it take?
When will it start helping?

7. Calculate expected return
Once the user selects a plan, WaterPilot moves from recommendation into implementation.
This is the:
“This looks good — how do we actually make it happen?”

stage.
The system estimates measurable returns.
For example:
Project cost: ₹8.2L
Estimated avoided tanker cost: ₹14.7L over 3 years
Estimated net benefit: ₹6.5L
Indicative payback: ~21 months

But this must be computed from actual assumptions and not hallucinated by Gemini.
The system should show those assumptions.
Example:
Tanker cost used:
₹X / litre

Expected reduction:
Y litres/year

Time horizon:
3 years

If we do not have reliable input data, we should clearly label the value as:
Illustrative estimate

or request more information.
8. Funding Matchmaker
Then WaterPilot asks:
“Do you need help funding this plan?”

The user may have:
Project cost: ₹8.2L
Community contribution: ₹3L
Funding gap: ₹5.2L

WaterPilot searches a curated database of funding opportunities.
Potential sources could include:
- municipal programs
- water-conservation grants
- climate funds
- CSR programs
- development-bank programs
- government schemes
The important thing is that these schemes must be loaded from real, verifiable documents.
The system does not just ask Gemini:
"What grants exist?"

Instead:
Grant documents
↓
Embeddings
↓
Firestore Vector Search
↓
Metadata filters
↓
Gemini explanation

The metadata can include:
Location eligibility
Applicant type
Project category
Funding size
Deadline
Required documents

Then WaterPilot might say:
Funding Match A
Match: 92%
Reason:
- location matches
- rainwater harvesting supported
- project cost within range
Eligibility:
Likely eligible — applicant status must be confirmed

This language is important.
We should not claim:
"You are definitely eligible"

unless every eligibility rule has been validated.
9. Generate a funding proposal
Once a funding option is selected, WaterPilot can generate a simple proposal.
For example:
Project Need
Current community water deficit
Proposed Solution
Rainwater harvesting + recharge wells
Budget
₹8.2 lakh
Expected Outcome
58% projected deficit reduction
Implementation Time
45–60 days
Community Benefit
Estimated households benefiting
Funding Request
₹5.2 lakh
Gemini is useful here because it converts structured project information into clear narrative.
Then WaterPilot produces a one-page PDF that the user can share with:
- RWA committee
- municipality
- CSR sponsor
- local grant body
- internal decision makers
10. Implementation plan
After funding or approval, the plan becomes a project.
Example:
Phase 1 — Planning & approvals
5–10 days
Phase 2 — Site preparation / installation
25–40 days
Phase 3 — Testing
5–10 days
Phase 4 — Monitoring
Ongoing
The user can track:
2/6 tasks completed
3/8 recharge wells installed
120 community members involved

So WaterPilot moves from "AI recommendation" into real execution tracking.
11. Track whether the prediction was right
This is the final feedback loop.
Before implementation:
Predicted deficit reduction: 58%

After implementation:
Actual deficit reduction: 49%

WaterPilot compares:
Predicted
vs
Observed

That allows us to improve future recommendations.
Conceptually:
Data
↓
Diagnosis
↓
Scenario
↓
Plan
↓
Execution
↓
Measurement
↓
Updated Water Twin

The system gets smarter because results feed back into the local model.
The complete user journey
In simple terms:
1. Understand
What is happening in my area?

↓
2. Test What-if
What happens if rainfall, demand or supply changes?

↓
3. Set Goal
What do I want to improve?

↓
4. Compare Plans
Which solutions fit my budget and timeline?

↓
5. Check Wider Impact
Does this help us without hurting nearby communities?

↓
6. Make It Happen
What does it cost?
What is the return?
Can we get funding?

↓
7. Execute
What are the actual implementation steps?

↓
8. Track
Did it actually improve the water situation?
